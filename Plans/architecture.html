1. Project Overview

A personal financial intelligence platform that continuously gathers market data, news, sentiment, and regulatory filings from free sources across the internet. It stores everything locally in PostgreSQL, serves a fast dark-mode dashboard via React, and sends Telegram notifications for critical events.

This is not a product or startup — it's a highly customized personal system for better market awareness, faster reaction to developments, and improved investment decision-making.

Key Principle: AI handles analysis and summarization only. Data collection is done through APIs, scrapers, and scheduled jobs — no AI in the critical data path.

5. Database Schema (High-Level)

5.1 Core Tables

-- Instruments being tracked
CREATE TABLE instruments (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10) UNIQUE NOT NULL,
    name        VARCHAR(255),
    type        VARCHAR(10) DEFAULT 'stock',  -- stock, etf
    sector      VARCHAR(100),
    is_owned    BOOLEAN DEFAULT FALSE,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Watchlists
CREATE TABLE watchlists (
    id          SERIAL PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE watchlist_items (
    watchlist_id  INT REFERENCES watchlists(id),
    instrument_id INT REFERENCES instruments(id),
    added_at      TIMESTAMPTZ DEFAULT NOW(),
    PRIMARY KEY (watchlist_id, instrument_id)
);

5.2 Time-Series (TimescaleDB Hypertables)

-- Intraday prices (retain 14 days)
CREATE TABLE prices_intraday (
    time        TIMESTAMPTZ NOT NULL,
    symbol      VARCHAR(10) NOT NULL,
    open        NUMERIC(12,4),
    high        NUMERIC(12,4),
    low         NUMERIC(12,4),
    close       NUMERIC(12,4),
    volume      BIGINT
);
SELECT create_hypertable('prices_intraday', 'time');

-- Daily candles (retain 1 year)
CREATE TABLE prices_daily (
    time        TIMESTAMPTZ NOT NULL,
    symbol      VARCHAR(10) NOT NULL,
    open        NUMERIC(12,4),
    high        NUMERIC(12,4),
    low         NUMERIC(12,4),
    close       NUMERIC(12,4),
    volume      BIGINT
);
SELECT create_hypertable('prices_daily', 'time');

5.3 Events & News (JSONB for flexibility)

-- News articles (retain 15 days)
CREATE TABLE news (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10),
    source      VARCHAR(50),
    title       TEXT NOT NULL,
    summary     TEXT,
    url         TEXT,
    metadata    JSONB,
    published_at TIMESTAMPTZ,
    fetched_at  TIMESTAMPTZ DEFAULT NOW()
);

-- SEC filings
CREATE TABLE filings (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10),
    form_type   VARCHAR(20),
    filer_name  VARCHAR(255),
    data        JSONB,
    filed_at    TIMESTAMPTZ,
    fetched_at  TIMESTAMPTZ DEFAULT NOW()
);

-- Sentiment scores
CREATE TABLE sentiment (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10),
    source      VARCHAR(50),
    score       NUMERIC(5,3),
    mentions    INT,
    data        JSONB,
    measured_at TIMESTAMPTZ DEFAULT NOW()
);

5.4 Alerts

CREATE TABLE alerts (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10),
    type        VARCHAR(50),       -- price_drop, volume_spike, news_trigger, etc.
    tier        VARCHAR(10),       -- critical, important, info
    title       TEXT NOT NULL,
    body        TEXT,
    data        JSONB,
    is_read     BOOLEAN DEFAULT FALSE,
    notified_at TIMESTAMPTZ,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE alert_rules (
    id          SERIAL PRIMARY KEY,
    symbol      VARCHAR(10),       -- NULL = applies to all
    type        VARCHAR(50) NOT NULL,
    tier        VARCHAR(10) NOT NULL,
    config      JSONB NOT NULL,    -- thresholds, conditions
    enabled     BOOLEAN DEFAULT TRUE,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

10. Portability & Deployment

  • Development: Current laptop. All code in this repo.
  • Production: Desktop PC. Clone repo, run docker compose up -d for Postgres, run start.ps1 for the app.
  • .env file: All secrets (Telegram token, API keys, OpenRouter key) in .env — never committed.
  • .env.example: Committed template showing required variables.
  • No backup needed: Data is re-fetchable. Postgres is ephemeral cache + recent history.
  • MCP/Hermes: Phase 6, built on desktop machine where Hermes is installed.

11. Key Design Decisions

Decision Log
  1. Free data only — no paid APIs for data collection. AI usage (OpenRouter) is the only cost.
  2. Separate processes — API server never blocked by collectors. Dashboard always fast.
  3. TimescaleDB — automatic retention, compression, fast time-range queries.
  4. Hybrid schema — relational for structured data, JSONB for messy/variable sources.
  5. AI is advisory only — it summarizes and suggests, never collects or acts autonomously.
  6. MCP is Phase 6 — build the platform first, agent integration second.
  7. One-way Telegram — bot pushes alerts, Hermes handles two-way conversation later.
  8. Monorepo — everything in one repo for simplicity and portability.
