1. What financePortal Is Now

financePortal is a financial intelligence pipeline — a personal background service that continuously gathers raw market data and news, pre-filters it for relevance, runs structured AI analysis on what matters, and stores pre-digested summaries that Hermes can read in seconds.

This is not a dashboard. Fidelity Tracker+ handles portfolio visualization. financePortal's only job is to make Hermes smarter about the user's portfolio — generating signals, distilling context, and delivering timely briefs.

Core Principle: Every stage is designed to reduce token cost. Raw data is filtered locally (free), relevant items go through FinBERT (free), only signal-worthy content hits DeepSeek (~$0.01/day). Hermes reads ~2,500 tokens per session from pre-built snapshots.
Daily Cost Target: ~$0.05  |  DeepSeek via OpenRouter: $0.27/1M input tokens  |  Expected daily input: ~150K tokens → ~$0.04

3.2 Pre-Filter Layer

Runs locally on every ingested item before anything touches an LLM:

  • Ticker regex — drop articles with no mentions of tracked symbols
  • Dedup hash — SHA-256 of title+source, skip if already processed
  • FinBERT — local transformer model, scores sentiment (positive/negative/neutral). Items below threshold skipped. Zero API cost.
  • Age gate — drop articles older than 48 hours at time of ingestion
FinBERT runs locally on CPU via Hugging Face transformers. ~0.2s per article. Pre-filters ~80-90% of raw volume — only high-relevance items reach DeepSeek.

3.3 Analysis Engine

DeepSeek R1 (distill) via OpenRouter. Runs in batches, never per-article in real-time.

-- Prompt template (structured extraction)
Given this financial news article, extract:
{
  "impact": "bullish|bearish|neutral",
  "affected_tickers": ["AAPL", "MSFT"],
  "key_facts": ["fact 1", "fact 2", "fact 3"],
  "urgency": "high|medium|low",
  "rationale": "one sentence why"
}

Article: {text}

Batch window: every 6 hours during market hours. Each batch: ~50–200 articles. Estimated 500 tokens/article average → ~$0.01–$0.03 per batch.

3.5 Context Builder

Assembles a compact snapshot for Hermes on demand. Target: <2,500 tokens total.

  • Latest brief (morning or evening) → ~800 tokens
  • High-urgency signals from past 24h → ~600 tokens
  • Per-ticker thesis for held positions → ~600 tokens
  • Price deltas for watchlist (compact table) → ~300 tokens
  • Buffer for Hermes tool calls → ~200 tokens

7. What We Are NOT Building

Explicit scope exclusions — do not build these:
  • ❌ React dashboard — Fidelity Tracker+ handles portfolio visualization
  • ❌ REST API for humans — no FastAPI server, no Swagger UI, no frontend
  • ❌ Real-time price feeds — 5-min polling is sufficient for intelligence
  • ❌ Custom charting — TradingView Lightweight Charts in a web app = waste of time
  • ❌ Alert UI / dashboard panels — Telegram is the only notification surface
  • ❌ Multi-user support — this is one person's personal tool
  • ❌ TimescaleDB — overkill; plain SQLite/Postgres is sufficient for this data volume
  • ❌ Docker Compose stack — SQLite for dev, bare Postgres install if needed; no Docker required

9. Key Design Decisions

  1. FinBERT before DeepSeek — free local model eliminates 80-90% of content before it touches a paid API.
  2. Batched analysis, not real-time — 6-hour batch windows keep costs predictable; nothing needs instant LLM response.
  3. Pre-digested snapshots — Hermes reads summaries, not raw data. 2,500 tokens vs. 250,000 tokens of raw articles.
  4. MCP as sole interface — no HTTP API, no dashboard polling. One clean tool surface for Hermes.
  5. SQLite-first — zero infra for a personal tool. Upgrade to Postgres only if concurrent writes become a bottleneck.
  6. Telegram for push, MCP for pull — push briefs proactively; Hermes pulls context on demand.
  7. No frontend = no maintenance — the pipeline is invisible infrastructure. All interaction is through Hermes or Telegram.
