⚡ Hermes — Personal AI Financial Advisor

Architecture design · financePortal · 2026-05-24

The Key Insight

Never feed raw data to the expensive model.
Pre-digest everything into structured intelligence packets on a schedule using cheap models. By the time the user asks Claude a question, a 2–4 KB curated brief is already waiting — not 50 KB of raw news. This makes every user query cheap, fast, and high-quality.

Components

1. Data Layer existing

  • prices_daily / prices_intraday — TimescaleDB hypertables, collected via Yahoo Finance every 5 min (market hours). No changes needed.
  • news — Finnhub articles, collected every 15 min. No changes needed.
  • instruments — Your universe of stocks; is_owned = true is the portfolio source of truth.

2. New DB Tables new

TableColumnsPurpose
briefssymbol, date, summary JSONB, generated_atPre-digested daily news per holding
alertssymbol, type, message, severity, triggered_at, dismissed_atRule-based material events
position_thesessymbol, thesis TEXT, risk_tolerance, target_price, updated_atYour buy rationale per holding — Hermes's long-term memory
conversationsid, role, content, model_used, tokens_in, tokens_out, created_atChat history + token tracking

3. Digest Engine new DeepSeek

Runs at 7 am ET via APScheduler (extending the existing scheduler). Fetches last 18 h of news for each is_owned symbol, calls DeepSeek with a tight prompt ("bullet-point what matters for a long-term holder"), stores the result in briefs. Cost: ~$0.001 per portfolio run. Idempotent — skips if today's brief already exists.

4. Alert Scanner new $0

Pure SQL job, runs every 2 h. Detects: price move ≥5% vs prior close, volume ≥3× 30-day average, earnings date = today (from instrument metadata), new FDA/SEC headline keywords. Writes structured rows to alerts. No AI involved — rules are deterministic and auditable.

5. Context Builder new $0

A single Python function called at the start of every /api/chat request. Runs one SQL query that joins portfolio positions, today's briefs, active alerts, theses, and the last 5 conversation turns into a ~2–4 KB JSON blob. That blob becomes the system prompt. The expensive model sees only curated facts.

6. Hermes Agent new

A new FastAPI router at /api/chat. Receives a user message, builds context, classifies query complexity (keyword heuristic — free), routes to the right model via OpenRouter, stores the turn, returns the response.

7. Frontend Chat Page new

A new React route in the existing app. Simple chat panel + morning brief card (from briefs table) + alert banner (from alerts). Talks to /api/chat. Reuses existing Tailwind/shadcn components.

Build Order (Phases)

  1. Phase 1 — Memory foundation
    Add briefs, alerts, position_theses, conversations tables. Seed initial theses for each holding.
  2. Phase 2 — Intelligence pipeline
    Digest Engine + Alert Scanner + Macro Digest jobs. Validate output quality without any UI.
  3. Phase 3 — Hermes agent API
    POST /api/chat with Context Builder, model router, function-calling tools. Test via curl before building UI.
  4. Phase 4 — Chat UI
    React page: chat panel + morning brief card + alert banner. Integrates into existing sidebar nav.
Why this architecture wins for a single-person portfolio:
The advisor is not a search engine — it's a knowledgeable colleague who already read the news before you asked. Scheduling intelligence ahead of user queries means the expensive model (Claude) only runs when you need genuine reasoning, not retrieval. The context it receives is curated, not dumped — so responses are faster, cheaper, and sharper.
