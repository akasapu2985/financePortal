⚡ financePortal — Implementation Plan

Version: 2.0  |  Revised: 2026-05-24  |  Status: Active (Pivot to Intelligence Pipeline)

Architecture Pivot: This plan replaces the 6-phase dashboard build. financePortal is now an intelligence pipeline for Hermes, not a dashboard product. 4 focused phases, ~$0.05/day operating cost, no frontend required.

Phase 1 — Foundation

🏗️ Collectors + Schema + Scheduler

Goal: Data flowing continuously into SQLite. The pipeline runs unattended on a schedule.

Tasks

  • Set up Python project with uv — pipeline/pyproject.toml
  • Create .env.example with all required env vars (Finnhub key, OpenRouter key, Telegram token)
  • Write Signal Store schema (store/schema.sql): tickers, articles, signals, briefs, theses, positions
  • Build store/db.py — SQLite connection with WAL mode, auto-migrate on startup
  • Build Yahoo Finance price collector (collectors/prices.py) — OHLCV every 5 min market hours
  • Build Finnhub news collector (collectors/news.py) — articles every 5 min, rate-limit aware
  • Build SEC EDGAR collector (collectors/filings.py) — Form 4, 8-K, every 30 min
  • Build APScheduler runner (scheduler.py) — registers all jobs, handles startup/shutdown
  • Create start.ps1 — one command launches the pipeline process
  • Add seed data: positions table with current portfolio symbols
  • Verify: articles and prices showing up in SQLite after 10 minutes of running

Deliverables

  • Pipeline process running on schedule, persisting data to SQLite
  • Prices, news, and filings collected continuously
  • Single uv run start or start.ps1 launches everything

Dependencies: None. This is the foundation.

Phase 2 — Intelligence

🧠 Filter + Analyze + Digest

Goal: Raw articles get filtered by FinBERT, relevant ones analyzed by DeepSeek, signals and briefs stored.

Tasks

  • Build dedup layer (filter/dedup.py) — SHA-256 hash of title+source, skip known articles
  • Build ticker regex filter (filter/ticker_regex.py) — drop articles with no tracked symbol mentions
  • Install + configure FinBERT (filter/finbert.py) — ProsusAI/finbert from HuggingFace, CPU inference
  • Build filter pipeline that chains: dedup → ticker match → FinBERT score → mark as filtered
  • Build OpenRouter client (analysis/client.py) — DeepSeek R1 distill, retries, cost logging
  • Write extraction prompt (analysis/prompts.py) — structured JSON: impact, tickers, key_facts, urgency
  • Build batch extractor (analysis/extractor.py) — collects pending filtered articles, batches to DeepSeek every 6h
  • Store extracted signals in signals table
  • Build brief generator (analysis/brief_builder.py) — calls DeepSeek to synthesize morning/evening brief from today's signals
  • Store briefs in briefs table with token count + cost logged
  • Verify: after market hours, morning brief is generated and stored in DB

Deliverables

  • FinBERT running locally, filtering ~80-90% of raw articles
  • DeepSeek analyzing remaining articles in 6h batches (~$0.01/day)
  • Morning + evening briefs auto-generated and stored
  • Cost log showing actual spend per day

Dependencies: Phase 1 (articles must be flowing into DB)

Phase 3 — Hermes

🔌 MCP Server + Telegram Delivery

Goal: Hermes can query the pipeline via MCP. Briefs arrive on Telegram automatically.

Tasks

  • Build Telegram client (delivery/telegram.py) — send formatted messages, handle markdown escaping
  • Schedule morning brief delivery (7:00 AM) and evening brief delivery (6:00 PM)
  • Add critical alert detection — high-urgency signals on held positions trigger immediate Telegram push
  • Build Context Builder (context/builder.py) — assembles <2,500 token snapshot from DB: brief + signals + theses + price deltas
  • Build MCP server (mcp/server.py) — Python MCP SDK, stdio transport
  • Implement MCP tools:
    • get_portfolio_snapshot() — positions + price deltas + P&L
    • get_morning_brief() — latest brief text
    • get_signals(ticker, days) — signals for a ticker in time window
    • get_thesis(ticker) — accumulated thesis text for a ticker
    • search_news(query) — top 5 relevant articles
  • Register MCP server in Hermes config on desktop machine
  • Verify: morning brief arrives on Telegram at 7 AM; Hermes can call get_morning_brief() and get the same text

Deliverables

  • Telegram briefs delivered 2x daily automatically
  • Critical alerts pushed immediately on high-urgency signals
  • MCP server running, Hermes connected
  • All 5 MCP tools working end-to-end

Dependencies: Phase 2 (briefs + signals must exist in DB)

Phase 4 — Advanced Signals

📡 Reddit, Insider Trades, Pattern Detection

Goal: Broader signal sources. The pipeline surfaces things no single news feed would catch.

Tasks

  • Build Reddit collector (collectors/reddit.py) — r/wallstreetbets, r/stocks; PRAW API; mention counts + tone
  • Build insider trade collector (collectors/insider.py) — Capitol Trades or Quiver Quant; Form 4 buys/sells for watched tickers
  • Build politician disclosure collector — STOCK Act disclosures; filter for watched tickers
  • Feed Reddit and insider sources through the same filter pipeline (FinBERT-compatible adapters)
  • Add new signal types: insider_buy, insider_sell, politician_trade, reddit_spike
  • Build pattern detector — identifies consecutive bearish signals, unusual volume + negative sentiment combos
  • Add thesis updater — when 3+ signals in 48h point the same direction on a held position, update the stored thesis
  • Add get_insider_activity(ticker) MCP tool
  • Verify: an insider trade on a held position generates a critical Telegram alert within 30 min of disclosure

Deliverables

  • Reddit sentiment feeding into signal store
  • Insider + politician trade tracking active
  • Pattern detection surfacing compound signals
  • Theses auto-updated from signal accumulation

Dependencies: Phases 1–3 complete. Reddit API credentials + Telegram bot configured.

What We Are NOT Building

  • ❌ React / Vite frontend — no dashboard UI
  • ❌ FastAPI REST server — no HTTP API for humans
  • ❌ Docker Compose — SQLite needs no infrastructure
  • ❌ TimescaleDB hypertables — plain SQL is sufficient
  • ❌ Alert tiers / dashboard alert UI — Telegram handles all delivery
