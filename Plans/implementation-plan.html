⚡ financePortal — Implementation Plan

Version: 1.0  |  Created: 2026-05-24  |  Status: Ready to Execute

Execution Strategy: Build in phases. Each phase produces a working, testable system. No phase depends on AI or external services that aren't built yet. The system works standalone from Phase 1 onward.

Phase 1 — Foundation (Get Data Flowing)

🏗️ Infrastructure + Core Data Pipeline

Goal: PostgreSQL running, schema created, price data flowing in, basic API serving it.

Tasks

  • Create docker-compose.yml with PostgreSQL 16 + TimescaleDB image
  • Create .env.example with all required environment variables
  • Set up Python project with uv — backend/pyproject.toml
  • Create database migration system (simple numbered SQL files)
  • Write initial migration: instruments, watchlists, prices_intraday, prices_daily tables
  • Write second migration: news, filings, sentiment, alerts, alert_rules tables
  • Build db/connection.py — async connection pool (asyncpg)
  • Build Yahoo Finance price collector (collectors/prices.py)
  • Build Finnhub news collector (collectors/news.py)
  • Build APScheduler runner (collectors/scheduler.py)
  • Build FastAPI app with health check endpoint
  • Build API routes: GET /instruments, GET /prices/{symbol}, GET /news
  • Create start.ps1 script to launch Postgres + API + Collector
  • Add seed data: initial watchlist with ~10-20 stocks for testing
  • Verify: prices flowing into DB, API responding with real data

Deliverables

  • Working Docker Compose stack
  • Python backend collecting prices + news on schedule
  • FastAPI serving data at localhost:8000
  • Swagger docs at localhost:8000/docs

Dependencies: None. This is the foundation.

Phase 2 — Dashboard MVP

⚛️ React Dashboard with Live Data

Goal: Open browser, see your stocks, charts, and news feed. Feels fast.

Tasks

  • Scaffold Vite + React + TypeScript project in frontend/
  • Install dependencies: TradingView Lightweight Charts, React Query (TanStack), Tailwind CSS
  • Build dark theme + CSS variables system
  • Build shell layout: top bar, left panel, center panel, right panel
  • Build portfolio/watchlist component (left panel) — compact table with day change, sparklines
  • Build TradingView chart wrapper component (center panel) — candlestick + volume
  • Build news/event feed component (right panel) — scrollable, categorized
  • Build top bar: search, market indices, portfolio total value
  • Build API service layer (services/api.ts) — typed fetch wrappers
  • Add React Query for data fetching with polling (refetch every 30s)
  • Build watchlist CRUD: add/remove stocks, create new watchlists
  • Add time range selector for charts (1D, 1W, 1M, 3M, 1Y)
  • Responsive behavior: panels collapse on smaller screens
  • Verify: dashboard loads in <1s, charts render smoothly, data updates live

Deliverables

  • Full command-center dashboard at localhost:3000
  • Interactive charts with real market data
  • Watchlist management
  • Auto-refreshing data

Dependencies: Phase 1 (API must be serving data)

Phase 3 — Alerts & Notifications

🔔 Event Detection + Telegram Alerts

Goal: System detects important events and pushes notifications to your phone.

Tasks

  • Build event detection engine (detection/engine.py) — runs on schedule, queries DB for trigger conditions
  • Implement detection rules: price drop ≥5%, volume spike ≥3x avg, stop-loss proximity
  • Implement news-based triggers: keyword matching, breaking news detection
  • Build alert dispatch system (notifications/dispatcher.py) — routes alerts to correct tier/channel
  • Build Telegram integration (notifications/telegram.py) — format messages nicely with emoji/links
  • Implement batching for 🟡 Important tier (aggregate every 30 min)
  • Add alert_rules table management API (CRUD for custom rules)
  • Build alerts panel in dashboard — show recent alerts, mark as read
  • Add alert badge/indicator to watchlist items when they have active alerts
  • Create Telegram bot via BotFather, document setup steps
  • Verify: trigger a test alert, see it arrive on Telegram within 2 min

Deliverables

  • Automatic event detection running continuously
  • Telegram notifications for critical + important alerts
  • Alert management in dashboard
  • Configurable alert rules

Dependencies: Phase 1 (data in DB), Phase 2 (dashboard for alert UI)

Phase 4 — Extended Data Sources

📡 More Intelligence, More Sources

Goal: Broaden the intelligence net — insider trades, politician disclosures, sentiment from social media.

Tasks

  • Build SEC EDGAR collector (collectors/filings.py) — Form 4 (insider trades), 8-K (major events)
  • Build politician trade collector (collectors/insider.py) — Capitol Trades or Quiver Quant scraping
  • Build Reddit sentiment collector (collectors/sentiment.py) — r/wallstreetbets, r/stocks mention counts + tone
  • Build X/Twitter sentiment collector — trending $cashtags, breaking news accounts
  • Add RSS feed aggregator — Reuters, MarketWatch, Seeking Alpha, Benzinga
  • Normalize all sources into common event format for detection engine
  • Add new detection rules: insider sell >$1M, politician trade on watchlist stock, sentiment spike
  • Enhance dashboard news feed with source categorization and filtering
  • Add sentiment indicator to watchlist items (mini gauge or color)
  • Verify: see insider trades, politician disclosures, sentiment scores flowing in

Deliverables

  • 5+ active data sources feeding the system
  • Insider + politician trade tracking
  • Social sentiment scoring per stock
  • Richer event detection with more signal types

Dependencies: Phase 1 (schema), Phase 3 (detection engine for new rule types)

Phase 5 — AI Analysis Layer

🧠 DeepSeek Intelligence

Goal: AI runs 2x daily, summarizes trends, tunes alerts, generates insights you couldn't get manually.

Tasks

  • Build OpenRouter client (ai/client.py) — handles DeepSeek Flash calls, retries, token management
  • Design prompt templates (ai/prompts.py) — morning brief, evening recap, stock deep-dive, alert tuning
  • Build daily analysis job (ai/analysis.py) — queries DB, assembles context, calls AI, stores results
  • Morning brief: portfolio summary, overnight news, key events today, risk flags
  • Evening recap: day performance, notable moves, sentiment changes, what to watch tomorrow
  • Alert tuning: AI reviews recent alert history, suggests threshold adjustments
  • Pattern detection: unusual correlations, sector rotation signals, momentum shifts
  • Store AI outputs in DB (new ai_insights table)
  • Add AI insights panel to dashboard — show latest analysis, recommendations
  • Send morning brief + evening recap via Telegram
  • Verify: receive coherent, useful morning brief on Telegram with real data

Deliverables

  • Automated 2x daily AI analysis
  • Morning brief + evening recap on Telegram
  • AI-powered alert tuning suggestions
  • Insights panel in dashboard

Dependencies: Phase 1-4 (needs rich data to analyze), OpenRouter API key

Phase 6 — MCP Server + Hermes Integration

🔌 Agent Access Layer

Goal: Hermes (or any MCP-compatible agent) can query and interact with the full financial intelligence system.

Tasks

  • Build MCP server (mcp/server.py) — SSE/HTTP transport, bearer token auth
  • Define MCP tools: get_portfolio, get_prices, get_news, get_alerts, get_sentiment
  • Define MCP tools (write): add_to_watchlist, create_alert, dismiss_alert
  • Define MCP tools (AI): get_latest_analysis, request_stock_deep_dive
  • Test with Hermes agent on desktop machine
  • Build Hermes skill definition for financial intelligence queries
  • Configure Hermes → MCP connection (network, auth)
  • Verify: Hermes can ask "How's my portfolio?" and get a real answer

Deliverables

  • MCP server running alongside API server
  • Full read+write tool surface for AI agents
  • Hermes connected and querying live data

Dependencies: All previous phases. Executed on desktop machine with Hermes.
